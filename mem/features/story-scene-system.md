동화 씬 길이는 대사/나레이션 분량에 맞춰 씬마다 따로 정한다. "한 씬 = 90초" 같은 고정 길이 규칙은 사용하지 않는다.

- 씬 길이는 해당 씬의 대사/나레이션 타임라인이 모두 끝나는 시점을 기준으로 산정한다. BGM/SFX 파일을 90초(또는 다른 임의 길이)로 자르지 않는다.
- BGM/SFX 파일이 씬 길이보다 길면 씬 종료 시점에 정지/초기화한다. 더 짧으면 필요에 따라 루프하거나 자연스럽게 페이드아웃한다. 어느 경우에도 다음 씬으로 잔향이 새지 않도록 cleanup을 보장한다.
- 각 씬은 배경, 캐릭터, 모션, 대사, 나레이션, BGM, SFX를 하나의 결정적 타임라인으로 묶는다.
- 다음 씬으로 넘어갈 때 이전 씬의 오디오/모션 상태가 남지 않도록 트랙 currentTime을 0으로 되돌리고 pause/cleanup을 보장한다.
- 재생/2배속/일시정지 설정은 BGM/SFX/모션 타임라인에 동일하게 반영되어야 하며, 수정이나 커밋 후에도 자동 실행 설정이 바뀌면 안 된다.
- 씬 완료 콜백은 씬 종료 시점에 한 번만 호출한다. 루프나 렌더 재시작으로 중복 전환이 발생하면 안 된다.
- 이 원칙은 현재 개미와 베짱이뿐 아니라 이후 제작하는 다른 모든 동화에도 기본 규칙으로 적용한다.

## 오디오 버스 구조 (씬 전환 끊김 방지)

- `src/lib/sceneAudio.tsx` 의 SceneAudio 버스가 모든 BGM/SFX HTMLAudioElement를 URL당 1개씩 소유한다. 씬 컴포넌트는 `useSceneAudio` / `useSceneTrack` 으로 URL을 "활성화"만 선언하며, 트랙 자체를 생성·재생·일시정지하지 않는다.
- 활성화는 refCount 방식이다. 동일 URL을 여러 씬이 acquire 하면 끊지 않고 이어 재생하며, 마지막 release 가 0으로 떨어질 때만 pause + currentTime=0 으로 초기화한다.
- release 는 setTimeout(0)으로 지연 실행한다. React StrictMode 더블 이펙트, 또는 씬 전환 시 cleanup → 새 mount 직후 같은 URL을 다시 acquire 하면 예약된 release 가 취소되어 오디오가 끊기지 않는다.
- 상태(BGM/SFX 볼륨, 음소거, playbackRate, speed) 변경은 patch → 모든 트랙 reconcile 로 즉시 일괄 반영된다. 씬 컴포넌트에서 직접 audio.play()/pause() 를 호출하지 않는다.
- 이 구조는 모든 동화의 씬 오디오에 동일하게 적용한다. 씬 추가 시에도 트랙 라이프사이클을 컴포넌트에서 직접 관리하지 말고 반드시 버스를 통한다.

## 대사·나레이션 원문 보존 원칙 (필수)

- 사용자가 채팅이나 이미지로 올린 대사·나레이션 텍스트는 **원문 그대로** 코드에 옮긴다. 문장부호, 띄어쓰기, 오탈자, 줄바꿈, 말줄임표까지 임의 수정 금지.
- 의미가 비슷하다는 이유로 문장을 다듬거나 요약·확장·재작성하지 않는다. "더 자연스럽게", "어린이가 이해하기 쉽게" 같은 자체 판단 윤문 금지.
- 사용자가 텍스트를 제공하지 않은 구간(예: 0–6s 도입 설명만 있는 구간)은 자체 생성한 임시 자막을 넣지 않고 비워둔다(`LINES`/`BEATS`에서 해당 구간 항목 자체를 생략).
- 다른 작업(레이아웃, 위치, 폰트, 색상, 모션, 오디오 등)을 수정하다가도 기존 `text` 문자열은 절대 건드리지 않는다. 패치할 때 `text` 라인은 변경 라인에 포함시키지 않는다.
- 사용자가 새로운 대사 원문을 올린 경우에만 교체하며, 그때도 원문 그대로 통째 치환한다. 불확실하면 추측하지 말고 사용자에게 원문을 다시 요청한다.
